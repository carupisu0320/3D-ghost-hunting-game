# 検査(npm test)

```
npm test                 # すべての検査(約2秒)。追加のインストールは不要(Node 18 以上)
npm run test:selfcheck   # 検査そのものの確認(約1分)。わざと壊して、検査が失敗することを確かめる
```

誰かが直したファイルを受け取ったら、まず `npm test` を実行して、全部通ることを確認する。

## 確かめていないこと(目で確認が必要)

- 実際の画面の見た目・操作感・ラグ(ブラウザで動かさないと分からない)
- 本物の socket.io の通信路。サーバーの試験は `lib/fake-socketio.js`(メモリ上の偽物)で動かしている。サーバーのルールは確かめられるが、WebSocket そのものは確かめていない
- Firebase(Googleログイン・Firestore)。お金の保存は、動作確認用の `MONEY_DEV=1` の保存先で確かめている
- engine.js の中身(幽霊の動き・ハント・調査書など)。import / export の整合と、報酬の式、難易度の一覧、読み込み(enterGame)の書き方だけを見ている
- 家具・壁・床の「見た目」そのもの(色・大きさ・汚れの具合)と、ロードにかかる時間・読み込み後のカクつき(ブラウザで動かさないと分からない)。計画(どこに置くか)だけを検査している
- `robot/` フォルダ(ロボットのモデルと画像)の存在

## 検査を足すとき

- `test/` の中に `○○.test.js` を作れば、`npm test` が自動で拾う(Node標準の `node:test` を使う)
- 「計算だけ」のブラウザ用ファイル(他のファイルや three を import しない)は、`helpers.js` の `loadEsm('ファイル名.js')` で読み込める
- 新しい検査を足したら、`self-check.js` の `MUTATIONS` に「わざと壊す方法」を1行足して、その検査が本当に失敗することを確かめる

## 静的な検査(任意): eslint

`npx eslint@10 .`(リポジトリ直下の `eslint.config.mjs` を使う)。`npm test` には含めていない。
`engine.js` を分割したあとに、「どこにも定義されていない名前」と「import した変数への代入」を見つける。
後者は、`let` の変数を別ファイルへ移したときに起きやすく、画面を開いて、その処理が動いた瞬間に初めて落ちる。
