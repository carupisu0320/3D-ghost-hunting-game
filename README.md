# マルチプレイ用ロビー(第一段階)

想定しているフォルダ構成:

```
プロジェクト/
  lobby-server/   (このフォルダ。サーバー)
  lobby-client/   (ロビー画面)
  game/           (これまで通りのソロプレイ用ゲーム本体)
```

ロビー画面には「1人で遊ぶ」ボタンがあり、これはサーバーに一切接続せず`../game/index.html`へそのまま移動します。サーバーを立てていなくても、これまで通りソロプレイだけは常に遊べます。

まだロビーとゲーム本編(幽霊調査パート)はつながっていません。「部屋を作る/コードで参加する→3D空間で歩き回れる→ホストが開始ボタンを押せる」ところまでの土台です。

## 1. サーバーを起動する

```
cd lobby-server
npm install
node server.js
```

`ロビーサーバー起動: ws://localhost:8080` と出れば起動成功です。ポートを変えたい場合は `PORT=9000 node server.js` のように環境変数で指定できます。

## 2. クライアント(ロビー画面)を開く

`lobby-client` フォルダは `type="module"` を使っているため、`index.html` をダブルクリックして直接開く(`file://`)のではなく、簡易サーバー経由で開いてください。例:

```
cd lobby-client
npx serve .
```

(または `python3 -m http.server` などでも構いません)

表示されたURL(例: `http://localhost:3000`)をブラウザで開きます。

## 3. 動作確認

1. 1つ目のタブ/ウィンドウで名前を入れて「部屋を作成」→ 発行された5文字の部屋コードをメモする
2. 別のタブ・別のブラウザ・別のPCから同じURLを開き、名前とその部屋コードを入れて「コードで参加」
3. お互いの画面にカプセル型のキャラと名前が表示され、WASD+クリックでの視点操作で歩き回れることを確認する
4. 部屋を作った側(ホスト)にだけ「ゲーム開始」ボタンが出るので押すと、参加者全員に開始が通知される(今はまだ本編には入らず、確認メッセージが出るだけ)

## サーバーを外部に公開する場合

友達と別々のネットワークから遊ぶには、`server.js` をどこかにホスティングする必要があります(Render、Railway、Fly.ioなど、Node.jsが動く環境ならどこでも構いません)。公開後は `lobby-client/lobby.js` 冒頭の `WS_URL` を、`wss://自分のサーバーのドメイン` に書き換えてください(`https`配信のページから`ws://`には接続できないため、`wss://`にする必要があります)。

## 今後やること

- ゲーム開始後、実際に `main.js` 側のゲームへ全員を接続する
- 幽霊の正解データ(種類・出没部屋・証拠)をサーバー側で決めて、クライアントには渡さないようにする
- 各プレイヤーの正気度・持ち物・EMFなどの証拠判定をサーバー経由で同期する
